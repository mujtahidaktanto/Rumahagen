# WF-01.05 — Authentication Scope v1.1

## Logical screens: 4 — unchanged
AUTH-01 Registration
AUTH-02 OTP Verification / Activation
AUTH-05 Login / Session
AUTH-06 Recovery / Reset

## Explicit M01 contract
- Registration creates the authentication entry flow.
- Successful OTP verification is sufficient for account activation.
- Canonical transition: `REGISTER → OTP VERIFIED → ACCOUNT ACTIVE`.
- There is no default `PENDING_REVIEW` gate after successful OTP.
- KTP is optional during activation.
- `ISI NANTI` / deferred KTP is not an activation failure and does not create Pending Review.
- KTP remains an identity/eligibility requirement and is not an RBAC permission.
- Verification Document is protected identity/eligibility information and is not public.
- Login/session establishes authenticated identity; authorization remains M10-controlled.
- Recovery/reset remains within authentication.

## Boundary to WF-01.06
WF-01.06 owns:
- AUTH-03 KTP Deferred Decision
- AUTH-04 KTP Completion / Verification Document Submission

WF-01.05 may show the transition point after activation but must not absorb the KTP workflow.
