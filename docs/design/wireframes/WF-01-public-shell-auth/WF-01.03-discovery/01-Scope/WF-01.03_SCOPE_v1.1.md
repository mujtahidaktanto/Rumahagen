## Correction
The screen count and package boundary are preserved. The correction is **screen-specific information
architecture**, so each discovery surface now represents the semantics of its authoritative domain
rather than using a generic result-card placeholder.

## Screen-specific IA
- **PUB-02:** cross-surface result type, title, summary, domain context, and open-detail route.
- **PUB-03:** Listing image, title/location, price, core property facts, public state/visibility where eligible,
  and detail CTA. Listing lifecycle remains M03-owned and is not managed here.
- **PUB-05:** public Agent identity, location/specialty, public review/outcome presentation where eligible,
  and public contact CTA where the source contract permits.
- **PUB-07:** public Organization identity, public overview, public member/listing summary where eligible,
  and public detail CTA. Membership management is excluded.
- **PUB-09:** Developer/Project identity, approved project representation, project media indication, canonical
  project summary, and detail CTA. Claim/admin operations are excluded.
- **PUB-11:** Event title, date/time, venue/format, public description, availability/quota indicator where
  authoritative, and registration entry CTA. Event Registration operations are excluded.
- **PUB-13:** Learning item/path identity, level/type, free/paid indicator where source-defined, eligibility/
  visibility indicator where applicable, and detail/session entry. Learning Economy transactions are excluded.

## Shared discovery rules
- Public discovery is not authorization.
- Visibility/indexability follows canonical domain state.
- No ranking algorithm is invented.
- Public Listing filters use AND logic.
- URL filter/query state may be shareable where applicable.
- Long content wraps; vertical scrolling is expected.
- No protected identity or private-resource existence is exposed.
