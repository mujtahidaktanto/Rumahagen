# WF-02.01 Visual Rules v1.1 — CORRECTED

## 1. UX
- One coherent goal per screen.
- Do not overload the screen just to reduce screen count.
- Vertical scroll is an approved normal behavior.
- Progressive disclosure/edit mode may be used inside a logical screen.
- Primary actions remain obvious and limited.

## 2. AGT-001 Dashboard
Dashboard is an M08 projection surface. It may summarize Listing, Learning, Event,
Commercial, Organization, Awarding and other domain state. It must not mutate source
truth. Notification visibility/redaction remains source-domain governed.

## 3. AGT-002 Agent Profile — mandatory coverage
The profile surface must account for:
- Agent Profile;
- Profile Photo;
- Profile Address: Provinsi, Kota, Area (Area remains free text);
- Organization Name as joined/created/operated organization context;
- Profile Statistics: Total Published Listings, Total Sold Listings, Total Rented Listings;
- Profile Visibility;
- Public / WhatsApp CTA explicit opt-in;
- Reviews presentation and applicable review actions/states;
- Outcome Presentation as a non-owning consumer.

M02 remains presentation authority; M01 owns identity/KTP, M03 owns Listing truth,
M12 owns organization semantics, upstream domains own outcome truth, and M10 owns
authorization.

## 4. Review semantics
Where the governed M02 review flow is shown:
Review submission → AUTO-APPROVE → Published / Viewable → Post-publication moderation.
Do not invent a default Pending Review gate.

## 5. Sensitive data
KTP/identity verification data must not be exposed through public-profile presentation.

## 6. Navigation
Desktop sidebar and mobile drawer/menu can hide/show/collapse. This is presentation
only and never an authorization boundary.

## 7. Dynamic content
Long Agent names, Organization Names, addresses, descriptions and review content wrap.
No new business character limits are invented. Truncation requires accessible full text.

## 8. States
Loading, Ready/Populated, Empty where applicable, Unauthorized/Protected,
Error/Retry, and Offline/Interrupted are required where applicable. Profile editing
also covers Dirty, Valid/Invalid, Submitting, Submitted and Server Error.

## 9. Responsive / accessibility
Desktop 1440px family; mobile 390px family; vertical mobile flow; no normal horizontal
overflow. Controls target approximately 44×44 CSS px or larger with adequate spacing.
Visible labels, focus, keyboard access, non-color-only status and semantic hierarchy.

## 10. Material-style visual language
Use the established uploaded WIRE-00/WIRE-01 shell language and the uploaded canonical
RumahAgen logo. Do not redesign the logo.

## 11. PHYSICAL/RUNTIME PROOF — NON-BLOCKING, MANDATORY
Absence of physical database proof, migration proof, API runtime proof, RLS proof,
runtime authorization proof, integration proof or production proof **MUST NOT lock,
HOLD, STOP or block WF-02.01 or any subsequent WIRE package**.

`NOT VERIFIED` is an evidence status, not a design prohibition.
A WIRE package may be blocked only by an unresolved semantic/authority/UX contradiction
that makes truthful representation impossible. Missing physical/runtime proof alone
is never sufficient.

When an exact physical identifier, endpoint, RLS policy or runtime state is not evidenced,
use the source-semantic concept/label and annotate the implementation dependency;
never invent identifiers.

No WIRE acceptance criterion may require physical/runtime proof.
