# WF-02.01 Visual Rules v1.0

## Screen decomposition
1. AGT-001 Dashboard is a projection surface, not a super-dashboard.
2. AGT-002 Profile is the authenticated Agent profile surface.
3. Keep the two goals separate. Do not combine Dashboard + Profile.
4. Long content scrolls vertically; never shrink type to fit one viewport.
5. Use progressive disclosure for secondary detail.

## Dashboard
- May summarize Listing, Learning, Event, Commercial, Organization, Awarding and other domain states.
- Summary cards are projections only.
- Notification content follows source-domain visibility/redaction.
- Notification actions may deep-link only to authorized destinations.
- Required states: loading, populated, empty, unauthorized, error, retry-sensitive.
- Avoid making every domain a full dashboard panel; prioritize the next useful action.

## Agent Profile
- Private profile editing is separate from public presentation.
- Sensitive identity/KTP data is never shown through public profile components.
- Public CTA is explicit opt-in under M02.
- Superadmin override remains an administrative authorization concern.
- Review outcome presentation must not become an authorization or award mechanism.
- AUTO-APPROVE is shown only where the governed review flow applies; no invented moderation gate.

## Navigation
- Desktop sidebar collapses/expands.
- Mobile uses compact top bar and drawer/menu.
- Navigation hide/show is not authorization.
- Agent context is independent-first; Organization context is not forced.

## Dynamic content
- Multi-line names/descriptions must wrap.
- No new business character limits are invented.
- Truncation is permitted only when full content remains accessible.
- Components must tolerate realistic long Agent names, descriptions and review outcomes.

## State & actionability
- Loading blocks conflicting duplicate actions.
- Empty explains the situation and gives a valid next action when one exists.
- Error preserves recoverable context where possible and offers retry.
- Unauthorized/restricted is distinct from technical error.
- Protected non-existence must not leak resource existence.
- Success reflects authoritative response, not client optimism.

## Responsive
Desktop reference: 1440px family.
Mobile reference: 390px family.
Mobile uses stacked cards and vertical flow; no horizontal overflow for primary content.
Tablet behavior: collapsible navigation and reduced density.

## Accessibility
WCAG 2.2 AA-oriented baseline:
visible labels, semantic heading hierarchy, keyboard/focus support,
non-color-only status, accessible control names, sufficient touch targets,
focus-safe dialogs/drawers, readable status feedback and reduced-motion support.

## Material-style visual language
Use the established WIRE-00/WIRE-01 shell as the visual family:
top app bar, collapsible navigation, cards, clear hierarchy, restrained surfaces,
consistent spacing and obvious primary CTA. The uploaded RumahAgen logo is the canonical brand asset.
